# Documentation Skill

## Purpose
Keep project documentation accurate, navigable and aligned with approved business requirements and actual implementation.

## Documentation types
- Product BRD: reusable product needs.
- CrossLife Pilot BRD: validated pilot-specific needs.
- Process maps: AS-IS and TO-BE.
- Requirements register: stable IDs and acceptance criteria.
- Decision register/ADRs: choices and rationale.
- API and developer docs: actual implementation contracts.
- Runbooks: deployment, backup, restore, monitoring and support.
- User guides: validated user workflows.

## Rules
Label content Confirmed, Proposed, To validate, Deferred or Out of scope. Date material decisions. Do not document planned behaviour as implemented. Do not claim legal compliance without evidence and qualified review. Keep examples free of real personal data.
