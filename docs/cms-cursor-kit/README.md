# Church Management System (CMS) — Cursor Agent Kit

This kit establishes the working instructions, project plan, Cursor rules, specialised skills and supporting registers for a reusable Church Management System. CrossLife Mission Network is the first pilot organisation, not the product name.

## How to use

1. Extract this folder into the root of the Church Management System (CMS) repository.
2. Review `PROJECT_CONTEXT.md` and `DECISIONS.md` with the project owner.
3. Keep the `.cursor/rules/` and `.cursor/skills/` directories in the repository.
4. Start Cursor Agent with the repository open. The root `AGENTS.md` provides shared project instructions; Cursor-specific rules and skills provide additional guidance.
5. Before implementation, complete the discovery items in `docs/discovery/` and approve the CrossLife Pilot BRD.

## Kit contents

- `AGENTS.md` — mandatory project-wide agent instructions.
- `agent-plan.md` — operating model and staged execution plan for the agent.
- `PROJECT_CONTEXT.md` — current product and CrossLife context.
- `ARCHITECTURE.md` — provisional architectural guardrails, not a final design.
- `IMPLEMENTATION_PLAN.md` — gated delivery sequence.
- `TASKS.md` — initial backlog and discovery tasks.
- `DECISIONS.md` — confirmed decisions and deferred questions.
- `CHANGELOG.md` — project change history.
- `.cursor/rules/` — Cursor project rules.
- `.cursor/skills/` — specialised reusable agent skills.
- `docs/` — BRD outline, discovery registers, process template and requirements template.

## Important status convention

Every substantive item must be labelled as one of:
- **Confirmed** — explicitly agreed or evidenced.
- **Proposed** — recommended but not yet approved.
- **To validate** — requires stakeholder confirmation.
- **Deferred** — deliberately postponed.
- **Out of scope** — not part of the current approved scope.

Do not silently turn a proposal into a requirement.
