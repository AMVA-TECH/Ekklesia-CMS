# Ekklesia i18n (English ↔ Kiswahili)

System-wide UI localisation. **Phase 0** ships the foundation; later phases translate remaining surfaces.

## Locales

| Code | Language   | Notes                          |
|------|------------|--------------------------------|
| `sw` | Kiswahili  | Default (pilot / Tanzania)     |
| `en` | English    | Secondary                      |

Aligned with DB enums: `people.preferredLocale`, church `defaultLocale`, message template `locale`.

## Resolution order

1. Cookie `ekklesia.locale` (explicit UI choice)
2. Signed-in `preferredLocale` (synced into the cookie on session load)
3. Church `defaultLocale` (future: anonymous / first visit)
4. Fallback `sw`

URLs are **not** prefixed (`/en/...`). Locale is cookie-based via `next-intl`.

## Message catalogs

- `messages/en.json`
- `messages/sw.json`

Keep keys identical across files. Nested namespaces by surface: `Landing`, `Auth`, `Common`, …

### Adding a string

1. Add the key to **both** `en.json` and `sw.json`.
2. Use `useTranslations('Namespace')` in client components or `getTranslations('Namespace')` in server components.
3. Do **not** hardcode user-visible copy in new UI.

## Language switcher

`<LocaleSwitcher />` from `@/app/_ekklesia/i18n/locale-switcher`:

- Sets cookie via `POST /api/locale`
- Optional `persistProfile` → `PATCH /api/v1/people/me` with `{ preferredLocale }`
- Calls `router.refresh()` so RSC trees re-render in the new locale

## Phases

| Phase | Scope |
|-------|--------|
| **0** | Foundation: catalogs, provider, switcher, landing + auth chrome — **done** |
| **1** | Auth screens (sign-in, register, verify, check-in) — **done** |
| **2** | Member portal (shell, home, profile + page titles) — **done** |
| **3** | Admin core (nav, chrome, dashboard + People/Households/Organisation/Messaging/Settings titles) — **done** |
| **4** | Admin deep modules (finance, events, attendance, governance + remaining list PageHeaders) — **done** |
| **5** | Outbound templates + API error localisation + CI key parity — **done** |
| **6** | Full UI sweep (shared chrome, auth metadata, member bodies, admin deep UI) — **done** |

## Outbound (Phase 5)

- **OTP SMS/email** use `Outbound` catalog strings in the recipient’s `preferredLocale` (else church `defaultLocale`, else `sw`).
- **Blast dispatch** from a message template picks the matching `code`+`channel` locale body per recipient when variants exist.
- **API errors**: problem+json `code` is on `ApiError`; UI should use `formatApiErrorMessage` / `useApiErrorMessage` from `@/i18n/api-error-message` with the `ApiErrors` catalog.

## CI

```bash
pnpm i18n:check
```

Fails when `messages/en.json` and `messages/sw.json` key trees differ. Wired into GitHub Actions and `pnpm check`.

## Out of scope

- Auto-translating free-text church content (announcements, names)
- Languages beyond `en` / `sw`
- Live audio interpretation
